## 2026-09-09 · v0.6.0 🛠 小工具版块（压缩图片 / PDF 转 Word / 一键抠图 / 抖音无水印）

**背景**：用户要求新增小工具版块（压缩图片、PDF 转 Word、抖音无水印、一键抠图），明确要求**基于成熟库实现，不手写**。抖音方案由子智能体先验证再接入。

### 新增

- **后端**（`server/src/tools.js`，Express Router 挂 `/api/tools/*`，multer 内存上传，单文件 ≤25MB）
  - `POST /compress`：**sharp** 压缩（EXIF 自动摆正、画质 10-95 可调、可限宽；透明图输出 WebP、其余 mozjpeg）
  - `POST /pdf2word`：**pdfjs-dist** 逐页提取文本（按 y 坐标聚行、行距分段）+ **docx** 生成 .docx（限 300 页；扫描件不支持，明确报错）
  - `POST /removebg`：**@imgly/background-removal-node** 本地 ONNX 模型（medium），推理串行化，输出透明 PNG
  - `POST /douyin` + `GET /douyin/file`：分享链接解析无水印视频 + 代理流式下载（透传 Range）
- **前端**（`ToolsView.vue` 单文件组件，导航「🛠 工具」，#/tools）
  - 工具卡片墙 → 工作台：文件点选/拖拽注入、压缩参数（画质滑杆/限宽）、结果预览（压缩前后对比、抠图棋盘格透明底对比、抖音封面+视频内嵌预览）与下载
- **`AppIcon.vue`** 新增工具类图标（image/scissors/file-text/download/video/wrench，纯新增）

### 关键技术结论（子智能体实测 + 本机复现）

- **抖音现行链路**（经典 iteminfo 接口已死，返回 0 字节）：分享文案提链 → 短链 302 取 video_id → **ttwid 注册**（ttwid.bytedance.com，缓存复用）→ 分享页 `window._ROUTER_DATA`（**手机 UA + ttwid cookie 缺一不可**，loaderData 键名为字面量 `video_(id)/page`）→ `douyin.com/aweme/v1/play/?video_id={uri}&ratio=1080p` 无水印直链（206 mp4，UA 不限）。全程无需 a_bogus 签名；签名 CDN 地址有时效，代理实时跟随不缓存
- **抠图原生库冲突**（本机实测踩坑）：imgly 依赖 `sharp ~0.32.4`，与顶层新版 sharp 同进程加载两份 libvips → **推理时段错误**（首跑成功、之后必崩，极难排查）。修复：顶层 sharp 锁定 0.32.4 单副本，连续推理稳定；模型首跑自动下载（网络可达）

### 测试

- 压缩：2400px 测试图 22.8KB→3.6KB（quality60+限宽1280）；GUI 注入 676KB 图 → 19.1KB（97%），预览/下载正常
- PDF 转 Word：构造 2 页文本 PDF → docx 生成，document.xml 含全部测试文本；GUI 全流程通过
- 抠图：HTTP 连续 2 次 200（~4s/张），输出合法 RGBA PNG；GUI 原图/透明底对比正常
- 抖音：短链分享文案（含 emoji）与 PC 直链两种输入均解析成功（标题/作者/封面/无水印地址），代理 Range 206；GUI 粘贴→解析→视频内嵌预览→下载按钮全通过
- 布局回归：新增「工具」导航后 390px 视口顶栏溢出 → 改为窄屏两行式顶栏（导航横向滚动），复测无溢出

### 已知限制

- PDF 转 Word 仅纯文本型 PDF（无 OCR）；版式/图片不保留
- 抖音为未公开接口，存在随时调整风险（已按缓存 ttwid + 实时拼播放地址降低失效面）；图集帖（note）走同一接口，前端当前按视频展示
- 抠图首次使用需下载本地模型（约百 MB 级，之后离线可用）；推理串行执行（CPU 密集）

## 2026-09-09 · v0.4.1 听书频道：完整测试 + 三项优化

**背景**：按「功能做完先测一遍 → 找优化点 → 继续优化再测」的要求，对 v0.4.0 做了两轮测试与一轮优化。

### 第一轮测试（全部通过）

- 后端边界：缺参 400、SSRF 拦截、未知源、坏章节（源站 404 → 明确报错不崩）、超长关键词 400
- 前端流程：换书搜索（凡人修仙传 4 个演播版本）、播第一章、进度条拖动 seek（0:27 → 8:27，源站支持 Range）、筛选、日间主题、移动端 390px 视口

### 测试发现的优化点（本轮全部落地）

1. **直链失效自动重解析**（`musicStore.js`）：听书直链 token 10 分钟过期、音频服务器会迁移，用户暂停半小时再播原本会失败并跳到下一集。现在 error 事件先对带 `resolve()` 的条目**重新解析当前集原地续播**（只自动重试一次，成功续播后复位，防止死循环；解析失败才走原有跳下一集逻辑）。实测：把 audio.src 换成坏地址 → 同一集重新解析出新 CDN 直链继续播，不跳集。音乐条目无 resolve 字段，行为完全不变
2. **章节筛选框**（`AudiobookView.vue`）：上千章找章节困难，章节网格上方新增即时筛选（>60 章的书才显示），支持编号与标题混搜（"药老"全书命中 9 集、"012"命中 12 集），显示命中数

### 一键启动脚本重写（2026-09-07）

- 修复 `start.bat` 浏览器先于服务打开导致的「无法访问」：改为 curl 轮询端口就绪（最多约 20 秒）后再打开浏览器，无 curl 时退化为固定等待 3 秒
- 新增端口占用检测：目标端口已有服务时直接复用并打开页面，不重复启动
- 支持自定义端口：`start.bat 3100`（Linux/macOS `bash start.sh 3100`），等效于 `PORT` 环境变量并已透传给后端
- `start.bat` 编码由 UTF-8 + `chcp 65001` 改为 GBK 无 chcp：修复 cmd 解析错位（边框 echo 行被当作命令执行）的问题
- `start.sh` 同步以上逻辑，`trap` 保证 Ctrl+C / 退出时正确停掉后端进程
- 新增 `NO_BROWSER=1` 环境变量跳过自动打开浏览器（用于脚本化与自动化测试）
- 实测：bat 端口占用分支、bat 全新启动轮询就绪、sh 全新启动（就绪探测 200 + 退出清理）均通过
