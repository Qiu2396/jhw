## 2026-09-07 · v0.2.2 新功能四件套（筛选排序 / 收藏 / 进度记忆 / 自动巡检）

**本次目标**：自主规划并新增四个高价值功能；每个功能落地前先做真实数据预验证，落地后逐项 GUI 验证。

### 预验证（先验证再动手）

- **类型归类规则**：抓取 6 个热门词的真实搜索结果，统计出 26 种源站类型名（国产动漫/脑洞悬疑/电影解说/爽文短剧/篮球…）。初版规则实测 3 处错分（动作片落其他、喜剧片因含"剧"字混进剧集、电影解说混进电影），修正为 v3 规则（`片$` 结尾归电影、解说单列、纪录片/预告片特例）后 31 个用例全部通过
- **自动巡检可行性**：实测并发探活 5 源一轮仅 1.5~5.6 秒，远低于超时预算，定时任务方案可行

### 新增

- **结果筛选与排序**（结果页）：分类 chips（全部/动漫/电影/剧集/解说/其他，带实时计数）+ 排序切换（默认/来源最多/最近更新），解决搜索结果混杂解说版/真人版的噪音问题
- **收藏功能**：结果卡片右上角星标（hover 显现），首页新增「⭐ 我的收藏」栏，点击直接打开播放
- **播放进度记忆**：每 15 秒自动保存进度 + 切集/换源/关闭时保存；「继续观看」续播自动 seek 到上次位置；弹窗新增「上一集/下一集」按钮与 0.5x~2x 倍速切换
- **源自动巡检**（后端）：启动 30 秒后首巡，此后每 6 小时自动探活全部源并写库（防重入），「站点目录」的最近检测状态自动保持新鲜

### 修复

- **续播 seek 不生效**：seek 原挂在 hls.js 的 MANIFEST_PARSED 事件，该时刻 video.duration 仍为 NaN，被 isFinite 守卫跳过；改挂 video 的 loadedmetadata 事件（once）后验证通过（第02集 80s 续播精确跳转）

### 验证（GUI 实测）

- 筛选：chips 计数与卡片实际归类一致（15+5+6+3=29），动漫筛选后 15 张卡全部为动漫类型；来源最多排序徽章数降序 3,2,1,1,1
- 收藏：星标点亮 → 首页收藏栏出现 → 点击收藏卡直接打开播放
- 进度：第01集 seek 到 300s 后切集，历史记录正确写入 progress=300；第02集关闭时 progress=80；续播后 video.currentTime=87.4（80s + 等待期播放），自动 seek 生效
- 倍速：1.5x 设置后 video.playbackRate 确认生效
- 巡检：服务启动 30s 后日志输出「巡检完成 5 源 / 5.597s，异常: ty」，结果写库

## 2026-09-07 · v0.2.1 界面样式整体优化

**本次目标**：不改动任何功能，系统性提升视觉质感，风格保持深色影院主题、更美观简洁。

### 变更（client/src）

- **全局设计体系**（style.css 重写）

  - 按钮体系统一（36px 高、hover 微上移 + 提亮，primary 金色渐变带光晕阴影，新增 danger 语义色）
  - 徽章统一高度与字色、滚动条加边距更精致、新增全局 keyframes（rise/pop-in/fade-in）与文字选中色
- **首页**（App.vue）：主标题加大至 40px 并对关键词做金色渐变字、logo 改为金色渐变圆角块、hero 入场动画、热门标签/特性卡片/继续观看卡片的 hover 反馈、页脚微调
- **搜索框**（SearchBar.vue）：加阴影与焦点光环（focus ring）、金色按钮带光晕、紧凑模式（顶栏）去阴影
- **结果卡片**（ResultCard.vue）：hover 上浮加深阴影 + 封面图片缓慢放大、备注角标毛玻璃化、卡片入场动画、徽章更细腻
- **播放弹窗**（PlayerModal.vue）：遮罩淡入 + 弹窗 pop-in 入场动画、弹窗边框/阴影层级、集数按钮与换源标签 hover 微交互
- **站点目录页**（SourcesView.vue）：AI 面板左侧金色渐变饰条、表格容器化 + 行 hover 高亮、开关/按钮统一新体系、弹窗动画、输入框焦点光环

### 修复

- 移除 body 的 `background-attachment: fixed`：该属性与多层径向渐变叠加会触发 Chromium 合成器异常（页面内容已在 DOM 与布局中正确存在，但截图/合成偶尔输出空帧，且浏览器捕捉接口超时）。移除后渲染稳定，视觉上几乎无差异。

### 验证

- 重新构建后浏览器实测：首页（渐变标题/品牌 logo/搜索框光晕）、结果页（29 组卡片网格）、站点目录页（AI 工具条/表格/开关）均渲染正常、截图确认

## 2026-09-07 · v0.2.0 SQLite 数据库 + AI 更新网站

**本次目标**：源配置从硬编码迁移到 SQLite 数据库（支持页面增删改）；新增 AI 能力，让 AI 自动发现、验证、收录新资源站。

### 新增

- **SQLite 数据层**（`server/src/db.js`）
  - 使用 Node 22 内置 `node:sqlite`（DatabaseSync），零外部依赖，单文件库 `server/data/app.db` 自动创建
  - 三张表：`sources`（源配置，含最近检测状态字段与来源标记 builtin/user/ai）、`settings`（键值配置，存 AI 服务信息）、`ai_logs`（AI 操作记录）
  - 首次启动自动把 `SEED_SOURCES` 灌入作种子
- **AI 模块**（`server/src/ai.js`）
  - ✨ **AI 发现新源**：LLM 按现有源状态推荐 macCMS 候选接口 → 后端逐个**真实请求验证**（能搜到内容才算通过，域名重复直接拒绝）→ 验证通过自动入库（origin=ai）→ 生成报告 + 写 ai_logs
  - 🩺 **AI 体检**：把各源最近检测结果交给 LLM，输出健康度结论与维护建议
  - AI 配置（Base URL / API Key / 模型名）存 settings 表，支持任意 OpenAI 兼容服务（DeepSeek/Kimi/智谱/通义/Ollama 等），环境变量兜底；GET 接口对 key 打码
- **后端新接口**：源 CRUD（POST/PUT/DELETE `/api/sources`）、检测并写库（POST `/api/sources/check`）、AI 五件套（config/test/discover-sources/analyze/logs）
- **前端站点目录页重构**（SourcesView.vue）
  - 工具条：新增源 / 一键检测 / AI 发现新源 / AI 体检 / AI 记录 / AI 设置（含已配置状态徽章）
  - AI 发现报告面板（可用/不可用/拒绝 + 耗时 + 已入库高亮）、AI 体检建议面板、AI 操作记录弹窗
  - 源表格：新增「最近检测」列与「检测/编辑/删除」操作列、AI 来源徽章；新增/编辑弹窗表单
  - API 封装扩展（api.js：源 CRUD、检测、AI 全套）

### 变更

- `aggregate.js` 搜索/详情改为从数据库读源（原 `sources.js` 的 `SOURCES` 改名为种子 `SEED_SOURCES`，仅在首次建库时使用）
- `tools/probe.mjs` 检测结果写回数据库
- 前端构建产物更新（含新版站点目录页）

### 验证（真实环境实测）

- 数据库：建库/种子迁移/CRUD/检测写库全通过；搜索改库后「凡人」69 组结果正常
- **AI 端到端**：用本地 OpenAI 兼容 mock LLM 实测全链路——AI 设置保存与连接测试 ✅；AI 体检返回分析文本 ✅；AI 发现 3 个候选（1 个真实可用未收录源、1 个假域名、1 个重复域名）→ 验证通过 1 个（红牛资源 682ms）自动入库 → 新源立即参与搜索 ✅ → 报告与日志正确 ✅
- 浏览器 GUI：站点目录页工具条/弹窗/报告面板/表格全部渲染正常（截图确认）

### 修复

- AI 推荐源的 id 规范化：中文 id 规范化后为空时，回退用接口域名生成有辨识度的 id
- `aggregate.js` 漏导入（v0.1.0 遗留记录见下）

### 说明

- `node:sqlite` 为 Node 22.5+ 实验特性，当前版本可用（有实验警告，无功能影响）；必要时可平替 `better-sqlite3`
- AI 功能需用户自配 LLM 服务（任何 OpenAI 兼容端点），未配置时页面有明确引导

## 2026-09-07 · v0.1.0 初版发布

**项目诞生**：从零搭建「免费视频网站聚合导航」完整可运行版本。

### 新增

- **后端**（`server/`，Node.js + Express）
  - `src/sources.js`：内置源定义——4 个启用源（暴风 / 极速 / 量子 / 360）+ 1 个默认停用源（天涯，接口异常），另有 6 个正版免费导航站（B 站、腾讯视频、爱奇艺、优酷、芒果TV、央视频）与热门关键词表
  - `src/aggregate.js`：核心聚合逻辑——macCMS JSON 搜索接口调用、GBK/UTF-8 自动解码、12s 超时熔断、`Promise.allSettled` 并发容错、按「标准化标题+年份」跨源去重聚合、`vod_play_url` 解析为线路→集数→m3u8
  - `src/index.js`：Express 入口——`/api/health`、`/api/sources`、`/api/search`、`/api/detail` 四个接口 + 生产模式托管前端构建产物（单进程单端口 3000）
  - `tools/probe.mjs`：源可用性检测 CLI（`npm run probe [关键词]`）
- **前端**（`client/`，Vue 3 + Vite + hls.js）
  - 首页：搜索框、热门词标签、继续观看（localStorage 播放记录）、功能介绍
  - 结果页：聚合卡片网格（封面、备注角标、来源徽章）、搜索状态条（条数/耗时/失败源提示）
  - 播放弹窗：hls.js 播放器、线路切换、站点换源、190 集级网格选集、Esc 关闭、移动端堆叠布局
  - 站点目录页：源表格（启用状态/一键检测/搜索开关）、正版导航卡片
  - 深色影院风 UI，hash 路由支持刷新与回退
- **一键启动**：`start.bat`（Windows）/ `start.sh`（Linux/macOS）——自动检测 Node、按需安装依赖、按需构建前端、启动服务并打开浏览器
- **文档**：`README.md`、`docs/设计文档.md`、本进度文档

### 关键验证（真实环境实测）

- 关键词「凡人修仙传」：29 组聚合结果，精确匹配的 2020 年番（更新至第190集）聚合 3 个源排首位

- 依赖：后端仅 `express`；前端 `vue / hls.js / vite / @vitejs/plugin-vue`

### 一键启动脚本重写（2026-09-07）

- 修复 `start.bat` 浏览器先于服务打开导致的「无法访问」：改为 curl 轮询端口就绪（最多约 20 秒）后再打开浏览器，无 curl 时退化为固定等待 3 秒
- 新增端口占用检测：目标端口已有服务时直接复用并打开页面，不重复启动
- 支持自定义端口：`start.bat 3100`（Linux/macOS `bash start.sh 3100`），等效于 `PORT` 环境变量并已透传给后端
- `start.bat` 编码由 UTF-8 + `chcp 65001` 改为 GBK 无 chcp：修复 cmd 解析错位（边框 echo 行被当作命令执行）的问题
- `start.sh` 同步以上逻辑，`trap` 保证 Ctrl+C / 退出时正确停掉后端进程
- 新增 `NO_BROWSER=1` 环境变量跳过自动打开浏览器（用于脚本化与自动化测试）
- 实测：bat 端口占用分支、bat 全新启动轮询就绪、sh 全新启动（就绪探测 200 + 退出清理）均通过
