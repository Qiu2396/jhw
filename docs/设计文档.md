# 设计文档 · 聚搜影视（免费视频网站聚合导航）

> 版本 v0.2.0 · 更新日期 2026-09-07

## 1. 目标与定位

用户想看某部作品（如《凡人修仙传》）时，不必逐个打开各个免费视频网站搜索——在本工具输入片名，即可：

1. 知道收录的哪些免费资源站有这部作品、更新到多少集；
2. 直接在站内选集播放（m3u8），支持换源、换线路；
3. 通过「站点目录」了解可用资源站与正版免费平台；
4. **AI 参与维护**：AI 推荐新源并自动真实验证入库、分析源健康给出维护建议。

**定位边界**：本工具是「聚合搜索 + 导航」工具，不存储、不上传、不转码任何视频；播放数据由后端实时调用第三方公开接口获取后直通播放器。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Vue 3 + Vite + hls.js | 组件化开发快；hls.js 让 Chrome/Edge/Firefox 也能播 m3u8（Safari 走原生 HLS） |
| 后端 | Node.js + Express（ESM） | 与前端同为 Node 生态，一键启动只需一个运行时；Express 单依赖足够 |
| 数据库 | **SQLite（Node 内置 `node:sqlite`）** | 零依赖、零配置、单文件（`server/data/app.db`）；Node 22 内置，无需原生模块编译 |
| AI | OpenAI 兼容 chat/completions（内置 fetch 直调） | 不绑定厂商：DeepSeek / Kimi / 智谱 / 通义 / OpenAI / 本地 Ollama 均可，页面可配 |
| 播放 | hls.js + `<video>` | m3u8 标准 HLS 方案，资源站通用格式 |

## 4. 数据库设计（SQLite）

文件：`server/data/app.db`，首次启动自动建库建表并灌入种子源。使用 Node 22 内置 `node:sqlite`（`DatabaseSync`），**无任何外部依赖**。

### sources（可搜索资源源）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 短标识，用于 URL 参数（如 bf / js） |
| name / api / web | TEXT | 名称 / macCMS 接口地址 / 前台地址 |
| tags | TEXT(JSON) | 标签数组，如 `["动漫","剧集"]` |
| enabled | INTEGER | 是否参与搜索 |
| note | TEXT | 备注 |
| origin | TEXT | 来源：`builtin`（种子）/ `user`（手动）/ `ai`（AI 推荐） |
| last_check_at / last_check_status / last_check_ms / last_check_info | | 最近一次检测的时间(unix秒)、结果(ok/fail)、耗时与说明 |

### settings（键值设置）

存 AI 配置：`ai_base_url` / `ai_api_key` / `ai_model`。环境变量 `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` 可作兜底。

### ai_logs（AI 操作记录）

`action`（discover / analyze）、`summary`（一句话摘要）、`detail`（JSON 明细）、`created_at`。

### 种子迁移

`sources` 表为空时自动灌入 `sources.js` 中的 `SEED_SOURCES`（内置 5 源）。**新增内置源**：编辑 `SEED_SOURCES` 后删除 `server/data/app.db` 重新初始化，或直接在页面「站点目录 → 新增源」添加。

## 5. 数据源设计（核心）

### 5.1 为什么用 macCMS 资源站

国内免费影视站绝大多数基于苹果CMS 搭建，其资源采集层提供**统一的公开 JSON 接口**，无需写爬虫解析 HTML：

- 搜索：`{api}?ac=videolist&wd=关键词` → `{code, total, list: [...]}`，含 `vod_id / vod_name / vod_pic / vod_remarks(如"更新至第190集") / vod_year / type_name / vod_time`
- 详情：`{api}?ac=detail&ids={vod_id}` → 含 `vod_play_from`（线路名）与 `vod_play_url`（播放地址串）

### 5.2 播放地址格式解析

`vod_play_url` 层级格式（线路间 `$$$`、集间 `#`、集名与地址间 `$`）：

```
第01集$https://…/01/index.m3u8#第02集$https://…/02/index.m3u8#…$$$线路2第一集$…
```

解析为 `{plays: [{from, episodes: [{name, url}]}]}`。

### 5.3 编码处理

部分站为 GBK 编码：先按 UTF-8 解码，检测到替换符 `\uFFFD` 时回退 `TextDecoder('gbk')`。

### 5.4 内置源（2026-09-07 实测）

| id | 名称 | 接口 | 状态 |
|---|---|---|---|
| bf | 暴风资源 | https://bfzyapi.com/api.php/provide/vod | ✅ 190集 |
| js | 极速资源 | https://jszyapi.com/api.php/provide/vod | ✅ 双线路 |
| lzi | 量子资源 | https://cj.lziapi.com/api.php/provide/vod | ✅ |
| zy360 | 360资源 | https://360zy.com/api.php/provide/vod | ✅（偶发超时） |
| ty | 天涯资源 | https://tyyszy.com/api.php/provide/vod | ⛔ 接口异常，默认停用 |

源失效排查：`cd server && npm run probe 凡人修仙传`（结果同时写回数据库）。

## 6. AI 模块设计（v0.2.0 新增）

### 6.1 能力一：AI 发现新源（「AI 更新网站」的核心）

流程 `POST /api/ai/discover-sources {autoAdd, count}`：

```
读取现有源及状态 → 构造提示词(含 macCMS 接口规范 + 现有源列表)
  → LLM 返回候选源 JSON
  → 逐个「真实请求验证」：调该接口搜索"凡人修仙传/斗破苍穹"
      ✅ 返回列表 → 可用；❌ 超时/无结果/不合法 → 不可用
      （与已收录域名重复 → 直接拒绝，不发请求）
  → autoAdd=true 时验证通过者自动入库（origin='ai'，id 冲突自动加后缀）
  → 写 ai_logs → 前端展示完整报告
```

**关键设计：AI 只负责「推荐」，是否可用由真实网络请求判定**——LLM 幻觉出的假域名会在验证环节被拦下，不会污染数据库。

### 6.2 能力二：AI 体检分析

`POST /api/ai/analyze`：把各源最近检测结果交给 LLM，输出整体健康度结论、异常源原因猜测、维护操作建议（文本）。

### 6.3 LLM 接入

- OpenAI 兼容 `POST {baseUrl}/chat/completions`，Bearer 认证，90s 超时
- 配置存 `settings` 表；页面「AI 设置」弹窗可填写并一键「测试并保存」；未配置时 AI 按钮返回明确错误提示
- 回复解析 `extractJson()`：兼容 markdown 代码块与前后缀说明文字

### 6.4 相关 API

| 接口 | 说明 |
|---|---|
| GET/POST `/api/ai/config` | 读取（key 打码）/ 保存 AI 配置 |
| POST `/api/ai/test` | 测试连接（回复"正常"） |
| POST `/api/ai/discover-sources` | AI 推荐新源 + 真实验证 + 可选自动入库 |
| POST `/api/ai/analyze` | AI 体检分析 |
| GET `/api/ai/logs` | AI 操作记录（最近 30 条） |
| GET `/api/music/search?name=` | 搜歌（歌名/歌手） |
| GET `/api/music/url?songId=` | 取免费播放直链 |
| GET `/api/music/lyric?songId=` | 取 LRC 歌词 |
| GET `/api/music/pic?songId=` | 取封面图 |

## 7. 音乐模块（v0.2.4 新增，替换电台）

数据源：**GDStudio 音乐聚合 API**（https://music.gdstudio.xyz ）——公益聚合服务，聚合各平台公开音源，无需 key。2026-09 实测仅 netease 音源可用。

- 后端 `server/src/music.js`：`searchMusic(name)` 搜索、`musicUrl(id, br)` 播放直链（320k 起，可命中无损 flac）、`musicLyric(id)` LRC 歌词、`musicPic(id, size)` 封面；响应解析对数组/对象均稳健，songId 强制数字校验
- 路由：`GET /api/music/search | url | lyric | pic`
- 前端「音乐」页：搜索歌名/歌手 → 歌曲列表 → 点歌即播；吸顶播放条（封面/无损徽章/上一首下一首）+ LRC 歌词面板（当前行高亮自动滚动）
- 兼容性：GDStudio 协议与 Meting 相近，若服务失效可替换 music.js 中 API 地址为任意兼容实例
- 电台功能（Radio Browser）已按需求移除

### 接入「听书」频道的预留说明

macCMS 音频资源站与视频源接口完全同构（`ac=videolist`，播放地址为 mp3/m4a），因此听书源一旦获得：在页面「站点目录 → 新增源」填入接口即可直接被聚合搜索；如需独立频道，可给 `sources` 表增加 `kind` 字段并在搜索路由按 kind 过滤（架构已预留）。


## 8. 小说模块（v0.2.5 新增）

与视频/音乐不同，文字小说站没有统一 JSON 接口。国内小说站绝大多数基于杰奇 CMS/笔趣阁模板，正文结构高度相似，因此采用**规则代理解析**：每站一套 CSS 选择器规则（格式沿用开源项目 so-novel 的规则体系），后端代抓 HTML 并提取数据。

- 规则文件：`server/src/novel-rules.json`（内置 4 个实测可用源：鸟书网/悠久/阅读库/顶点）
- 引擎：`server/src/novel.js` —— 搜索（GET/POST、UTF-8/GBK 自适应）、目录解析（含目录在章节页的 fallback）、正文清洗（去广告标签与文案、段落还原）
- 路由：`GET /api/novel/search?kw=`、`GET /api/novel/toc?src=&url=`、`GET /api/novel/chapter?src=&url=`
- 安全：目标 URL 的 host 必须命中收录源白名单（防 SSRF）
- 依赖：cheerio（选择器）、iconv-lite（GBK 表单编码）
- 前端「小说」页：搜索 → 书列表（来源徽章）→ 章节目录（多源切换）→ 阅读器（排版缩进、字号调节、上下一章、进度记忆）

## 10. 前端设计

单页三视图（hash 路由）：首页（搜索/热门词/继续观看）、结果页（聚合卡片网格）、站点目录（源管理 + AI 面板）。播放弹窗含 hls.js 播放器、换源、线路、集数网格；播放记录写 localStorage「继续观看」。

**站点目录页（v0.2.0 重构）**：

- 工具条：新增源、一键检测、✨AI 发现新源、🩺AI 体检、AI 记录、⚙AI 设置（含配置状态徽章）
- AI 发现报告面板：候选源表格（可用/不可用/拒绝 + 耗时 + 已入库高亮）
- 源表格：状态、AI 来源徽章、最近检测（状态/耗时/时间）、操作（检测/编辑/删除）、搜索开关
- 新增/编辑弹窗（名称/接口/前台/标签/备注/启用）；AI 设置弹窗（Base URL/模型/API Key + 测试连接）

## 11. 安全考虑

- **SSRF**：后端只请求 `sources` 表内的域名；`vid` 强制数字校验；新增源的 URL 必须以 http(s):// 开头
- **AI 幻觉防护**：AI 推荐的源必须通过真实接口验证才入库；重复域名直接拒绝
- **API Key**：存本机 SQLite，GET 接口只返回打码值（`sk-abc****`）
- **无存储**：服务端不存任何用户行为数据；播放历史/搜索开关仅存浏览器本机

## 12. 一键启动流程（start.bat / start.sh）

1. 检查 Node.js → 2. 按需 `npm install`（server/client）→ 3. 按需 `vite build` → 4. 启动服务（3000）并打开浏览器。SQLite 数据库在服务启动时自动创建，无需任何手工步骤。

## 13. 已知限制与后续方向

- AI 推荐质量取决于所配 LLM 的知识与温度，假源会被验证环节拦截但可能全部不可用（多跑几次或换更强模型）
- 资源站域名失效需手动更新或跑 AI 发现；可考虑定时探活 + 自动触发 AI 修复
- `node:sqlite` 目前为 Node 实验特性（Node 22.5+），API 如有变动需跟随升级；必要时可平替 `better-sqlite3`
